# Разрешение на аппаратную разработку

Дата решения владельца: `2026-09-03`.

Неисправный сервопривод левой руки физически отключён от платы. Прежний общий
запрет на работу с живым роботом снят только для задач, где перед действием
подтверждены отключённая левая рука, no-motion preflight, backup, verify и
rollback. Для разработки `GOSHA_FIRMWARE` разрешено:

- подключать робота по USB и использовать serial console;
- собирать, обновлять и устанавливать прошивку профиля `gosha-v1`;
- включать, выключать и перезагружать устройство ради проверки;
- выполнять только неподвижные проверки локального WebSocket и других
  интерфейсов робота.

Команды движения, `Home`, `set_trim` и servo sequence этим решением не
разрешены. Для них требуется отдельная явная команда владельца и новый
механический preflight.

Отдельное разрешение владельца перед каждым техническим шагом внутри
согласованной hardware-window задачи не требуется, но сама задача должна быть
явно задана владельцем. Замена левой сервы не является обязательным условием
для flash, reboot и update, пока левая рука подтверждённо отключена; для
motion, `Home`, `set_trim` и servo sequence замена или отдельный механический
допуск обязательны.

## Перед включением, reboot, update и flash

1. Визуально подтвердить, что неисправная левая серва всё ещё отключена от
   платы. Не подключать её обратно до ремонта или замены.
2. Поставить робота устойчиво и оставить питание доступным для немедленного
   отключения.
3. Зафиксировать точный commit, профиль `gosha-v1`, сборочную конфигурацию и
   способ отката. Сохранить предыдущий рабочий образ либо воспроизводимый
   способ его восстановления.
4. Использовать только рассчитанный для задачи набор разделов. Не стирать NVS,
   `otadata`, таблицу разделов или загрузчик без явной необходимости и backup.
5. Проверить, что сценарий не содержит motion-команд, `Home`, `set_trim`,
   servo sequence или внешних команд движения.

## Во время проверки

1. Не отправлять команды движения, `Home`, `set_trim` или servo sequence.
2. Немедленно остановить тест при неожиданном движении, перегреве, постороннем
   звуке, повторном reset, brownout или потере управления.
3. Не подталкивать неисправный или отключённый привод под питанием.
4. Raw TCP/WebSocket `:8080` использовать только при свободном односессионном
   `WSControl` и закрывать сразу после проверки.
5. Не выводить в serial-лог или Git Wi-Fi-пароли, реальные endpoints, device
   keys, токены, MAC-адреса или другие закрытые значения.

В задаче и Draft Pull Request записать установленный commit, команды проверки,
результат write/verify, фактический smoke и откат, если он выполнялся.
Разрешение на аппаратную разработку не разрешает автоматически merge,
production deployment или изменение рабочих серверов.

## Зафиксированная evidence PR `#33`

На `2026-09-03` PR `#33` уже прошёл hardware-window без новых команд движения:
app-only flash из `c81d24c941be8cadd6a96c9bbddd2884bf5906ae`, отдельный
`verify_flash` и короткий serial smoke. Подтверждены boot, Wi-Fi, OTA/config,
runtime events, локальный WebSocket и `idle` без panic/watchdog, brownout или
reset loop; servo LEDC warnings по выводам приводов исчезли. NVS, `otadata`,
bootloader, partition table и assets не менялись; rollback не потребовался.
Эту evidence не повторять как новый тест без отдельной hardware-window задачи.

Этот документ отменяет более ранние текущие инструкции, которые запрещали
flash или сводили работу к read-only до замены сервы, только для USB/serial,
сборки, flash, update, reboot, power-cycle и неподвижных проверок. Запрет
`no motion` сохраняется.
Старые checkpoint-факты о том, что раньше не выполнялось, остаются историей и
не блокируют разрешённую новую работу.
