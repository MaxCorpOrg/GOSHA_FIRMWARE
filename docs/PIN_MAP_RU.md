# Карта аппаратных выводов `GOSHA_FIRMWARE`

## Статус

- Эта карта пока предварительная.
- Основана на `main/boards/otto-robot/config.h` из канонической исходной базы.
- Для первой версии `gosha-v1` приоритетным считается вариант `non-camera`, пока не доказано обратное на реальном устройстве.
- `2026-09-03`: в ветке `codex/noncamera-pinmap-ledc-fix-20260903` программный конфликт `GPIO12` убран: правая рука остаётся на `GPIO12`, а `display_cs_pin` в `NON_CAMERA_VERSION_CONFIG` переведён в `GPIO_NUM_NC`. Статический guard `firmware/scripts/check_gosha_v1_pinmap.py` проверяет отсутствие дублей активных non-NC GPIO в критичных ролях.

## Что проверить перед реальными аппаратными правками

- не конфликтуют ли выводы дисплея и сервоприводов в реальном устройстве;
- совпадает ли разводка аудио с предварительным вариантом;
- действительно ли первая тестовая плата без камеры;
- нет ли отличий по питанию и батарее относительно исходного профиля `otto-robot`.

## Уже замечено в живом журнале

- Первый тестовый запуск определил устройство как вариант `non-camera`.
- В журнале есть предупреждения `ledc`, что требуют отдельной проверки пригодности выводов:
  - левая нога `GPIO17`
  - правая нога `GPIO39`
  - левая стопа `GPIO18`
  - правая стопа `GPIO38`
  - левая рука `GPIO8`
  - правая рука `GPIO12`
  - подсветка дисплея `GPIO3`
- Пока эти выводы нельзя считать окончательно неверными, но и нельзя считать подтверждёнными без отдельной аппаратной проверки на реальном движении и яркости подсветки.
- При этом локальный сервер управления уже стартует, то есть спор по этим выводам пока выглядит как аппаратный риск для движения и подсветки, а не как причина полного сбоя запуска прошивки.
- На новом устройстве `2026-08-23` перекрёстный тест рук подтвердил левый канал `GPIO8`: исправный правый сервопривод двигался после подключения к левому разъёму.
- Физический сервопривод левой руки не запускался и на рабочем правом канале, поэтому его отказ нельзя использовать как доказательство неверного `GPIO8`.
- Для рук текущая степень уверенности разделяется так:
  - `GPIO8` как управляющий вывод левого канала подтверждён перекрёстным тестом;
  - `GPIO12` как управляющий вывод правого канала подтверждён фактическим движением исправной сервы;
  - механическое домашнее положение и точная модель сервопривода требуют повторной проверки после замены неисправного узла.
- В коде `gosha-v1` `display_cs_pin` для `non-camera` теперь отключён через `GPIO_NUM_NC`, поэтому правый канал руки больше не делит активный вывод с `display_cs`. Это не заменяет будущую физическую проверку пригодности остальных `LEDC`-выводов.
