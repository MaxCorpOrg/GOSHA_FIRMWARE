# Контрольная точка: временная безопасная нейтраль

Дата: `2026-09-04`.

## Причина

Установленный no-motion образ PR `#48` намеренно не подключает сервоприводы и
не выполняет boot `Home`. Поэтому оставленный без механической опоры робот
складывается под весом корпуса. Обычный `Home` применять нельзя: он командует
всем настроенным каналам, включая физически отключённую левую руку, и открывает
общий контур движений.

## Решение

В отдельной ветке от exact head PR `#48` добавлен временный build-вариант
`gosha-v1-safe-neutral-boot`.

- `CONFIG_GOSHA_NO_MOTION_SAFE_PROFILE=y` остаётся обязательным.
- `CONFIG_GOSHA_SAFE_NEUTRAL_BOOT_PROFILE=y` разрешён только вместе с
  no-motion и по умолчанию выключен.
- Оба канала рук заменяются на `GPIO_NUM_NC` до подключения сервоприводов.
- Только при полном non-camera наборе четырёх каналов ног и ступней они
  подключаются и один раз за запуск получают удержание `90` градусов.
- Camera-вариант и неполный нижний pin set завершаются без servo PWM.
- MCP/raw WebSocket/серверные movement, `Home`, trim и sequence остаются
  закрыты; удалённые reboot, OTA и assets write также не открываются.

## Механическое ограничение

Обратной связи по углу нет. Внутренняя координата сервопривода после attach
начинается с `90` и не отражает свободную физическую позу. Поэтому обещать
плавный автоматический подъём из произвольного положения нельзя. До запуска
оператор вручную, без питания и без усилия, приближает ноги и стопы к
нейтрали, держит корпус и оставляет выключатель питания доступным.

## Граница установки

Устанавливается только app-раздел после свежего backup текущего app-slot.
NVS, `otadata`, bootloader, partition table и assets не меняются. Запись
выполняется без автоматического запуска нового образа; первый запуск делается
отдельно при физической поддержке корпуса. После записи обязателен отдельный
`verify_flash`. PR остаётся Draft/Open и не сливается.

## Сборочная проверка

Каноническая локальная сборка ESP-IDF `5.5.2` с безопасным адресом `.invalid`
прошла. В итоговом `sdkconfig` одновременно подтверждены
`CONFIG_GOSHA_NO_MOTION_SAFE_PROFILE=y` и
`CONFIG_GOSHA_SAFE_NEUTRAL_BOOT_PROFILE=y`. App-образ имеет размер `3615536`
байт, SHA-256
`6c830d8870eb31f2008ea1e590d66f3fa24d779ef918ee77515e2ba7916dd03b`;
в app-разделе свободно `0x7d4d0` байт, то есть `12%`.

Точный commit `baf0323d17db9f0635cf9ae64d79eb6f3c19af2c` прошёл
независимый read-only review: `PASS`, `P0/P1/P2=0/0/0`. Проверены
изоляция maintenance build, `default n`, оба канала рук `NC`, ровно
четыре нижних канала, fail-closed camera/partial pin set и закрытые
внешние motion/OTA/reboot/assets-write пути.

## Фактическая установка

Перед записью свежий readback всего текущего app-slot PR `#48`
сохранён как owner-only файл mode `0600`:

- размер `4128768` байт;
- SHA-256
  `333a0e71429d3b5431e456dc6a0fb75bfe9f3e948203a48beedecf301ea469b8`;
- prefix совпал с точным canonical app-образом PR `#48`.

Образ safe-neutral записан только в app-раздел по offset `0x20000`
с отключённым автозапуском. Затем отдельный `verify_flash` подтвердил
точное совпадение digest. NVS, `otadata`, bootloader, partition table
и assets не записывались.

Перед первым запуском владелец подтвердил физическую поддержку
корпуса, предварительную установку ног и стоп близко к нейтрали,
физически отключённую левую руку и доступное аварийное отключение
питания. Пассивный serial интервал примерно от `45` до `95` секунд
показал стабильную работу, свободную SRAM и сетевое соединение;
panic, watchdog, brownout и reset loop не зафиксированы. Ранний boot-log
в этот serial-интервал не попал, поэтому одноразовый boot marker не
считается live-подтверждённым.

## Открытая физическая проверка

Владелец сообщил, что правая рука не работает. Для этого образа это
ожидаемо: оба канала рук намеренно `GPIO_NUM_NC`, поэтому правая
рука временно свободна от PWM, а не повреждена. Физический итог
удержания ног, отсутствие сильного гула/дрожи/нагрева и поза робота
на момент остановки ещё не подтверждены.

Первый шаг на следующую сессию: до любой новой прошивки, reset
или motion-команды владелец подтверждает текущую позу, гул/дрожь и
нагрев. Затем отдельно решается, нужен ли узкий профиль
`ноги удерживаются + правая рука разрешена + левая рука NC`. Такой
профиль ещё не реализован и не установлен.
