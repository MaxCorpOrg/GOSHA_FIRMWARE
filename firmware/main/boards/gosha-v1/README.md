# gosha-v1

Профиль `gosha-v1` — первая собственная точка прошивки `Гоша`, созданная как безопасная копия профиля `otto-robot`.

## Назначение

- сохранить исходный `otto-robot` как эталон сравнения;
- вынести собственные аппаратные и продуктовые правки в отдельный профиль;
- подготовить первую самостоятельную сборку `Гоша` без вмешательства в исходный профиль.

## Текущее состояние

- Профиль уже содержит собственные продуктовые параметры `Гоша`, экранный профиль, локальный управляющий контур и подтверждённый объединённый образ.
- На новом устройстве `2026-08-23` подтверждены `ESP32-S3` ревизии `v0.2`, вариант `non-camera`, `16 MB` flash-памяти и `8 MB PSRAM`.
- Полная установка потребовалась из-за несовместимой заводской таблицы разделов и выполнена только после полного резервного копирования flash-памяти.
- Программный канал левой руки на `GPIO8` подтверждён перекрёстным тестом.
  Неисправный физический сервопривод левой руки отключён от платы и должен
  оставаться отключённым. Прошивка, перезагрузка и неподвижные аппаратные
  проверки разрешены по `docs/HARDWARE_DEVELOPMENT_POLICY_RU.md`; движение
  требует отдельной команды.
- Полная аппаратная проверка опирается на документы верхнего уровня:
  - `../../../../docs/HARDWARE_MANIFEST_RU.md`
  - `../../../../docs/PIN_MAP_RU.md`
- Текущий безопасный release-кандидат включает
  `CONFIG_GOSHA_NO_MOTION_SAFE_PROFILE=y`. В этом режиме профиль поднимает
  голос, `Wi-Fi`, OTA/config, runtime events и локальный `WebSocket`, но не
  подключает сервоприводы, не выполняет boot `Home` и не регистрирует
  MCP-инструменты движения, servo sequence, `set_trim` и ручной
  `self.upgrade_firmware`. Замена прошивки во время работы также отклоняется в
  `Application::UpgradeFirmware()` до закрытия `protocol`, остановки `audio`,
  загрузки образа, записи flash-памяти или reboot. Удалённое MCP-действие
  `self.reboot` в этом профиле не регистрируется, а прямые MCP-вызовы
  `self.upgrade_firmware`, `self.reboot` и `self.assets.set_download_url`
  отклоняются до побочных эффектов. `CheckAssetsVersion()` в этом профиле не
  открывает `assets/download_url` на запись и не запускает живую замену
  ресурсов; `Assets::Download()` возвращает отказ до HTTP и записи
  flash-памяти. Уже установленный локальный assets-раздел применяется.
  Серверная команда `system.command == "reboot"` тоже отклоняется до
  `Application::Reboot()`. Возврат движения, удалённого reboot или удалённой
  замены assets допускается только отдельным аппаратным решением и отдельной
  сменой сборочного параметра.

## Ближайшие шаги

- сохранить Draft/Open состояние PR `#24`, а новые устанавливаемые кандидаты
  готовить в отдельной ветке с rollback и hardware evidence;
- подобрать совместимую замену левой сервы, сначала проверить её без качалки и нагрузки, выполнить `Home` и только затем установить механику;
- после замены провести малый тест руки штатным управляющим путём;
- продолжить подтверждение остальных строк аппаратного манифеста и карты выводов;
- для последующих выпусков использовать каноническую сборку `GOSHA_OTA_URL='<owner-only endpoint>' python3 scripts/release.py gosha-v1 --name gosha-v1`; скрипт не печатает значение endpoint и не хранит его в Git.

## Временная сборка безопасной нейтрали

Вариант `gosha-v1-safe-neutral-boot` предназначен только для отдельно
разрешённого владельцем возврата корпуса в нейтральную стойку. Он одновременно
оставляет включённым `CONFIG_GOSHA_NO_MOTION_SAFE_PROFILE` и добавляет
`CONFIG_GOSHA_SAFE_NEUTRAL_BOOT_PROFILE`.

- оба канала рук перед инициализацией контроллера заменяются на
  `GPIO_NUM_NC`, поэтому PWM на руки не подаётся;
- на варианте `non-camera` подключаются только четыре привода ног и ступней;
- при каждом запуске образ один раз подаёт на них нейтральное удержание
  `90` градусов и затем сохраняет PWM для удержания стойки;
- если обнаружен вариант с камерой либо неполная карта четырёх нижних
  приводов, все servo PWM остаются отключёнными;
- внешние инструменты движения, `Home`, `set_trim`, servo sequence, удалённые
  reboot/OTA и живая замена assets остаются закрыты no-motion профилем.

У сервоприводов нет обратной связи. Прошивка не знает фактический угол
свободного сустава и не может достоверно выполнить плавный переход из
произвольной сложенной позы. До запуска оператор обязан при снятом питании
поставить стопы плоско, приблизить ноги к нейтрали без усилия, удерживать
корпус и иметь немедленный доступ к отключению питания. При рывке, гуле,
нагреве, повторном reset или brownout питание отключается сразу.

Каноническая локальная сборка временного варианта:

```bash
GOSHA_OTA_URL='https://maintenance.invalid/firmware/' \
  python3 scripts/release.py gosha-v1 --name gosha-v1-safe-neutral-boot
```

Адрес `.invalid` служит только безопасной заглушкой для локальной сборки;
полученный образ не предназначен для удалённого обновления.
